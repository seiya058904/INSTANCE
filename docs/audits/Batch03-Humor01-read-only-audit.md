# Batch03 / Humor01 只读内容审计报告

## 1. 总体结论

### Batch03

整体质量中上，实用性稳定，但新增价值主要来自题材和用户身份，而不是新的 HumanBehaviorMode。

优点：

- 用户问题普遍可信，事实边界和回复质量较稳。
- 家长、轮班工作者、社区管理员、小店经营者等身份补充有效。
- 很少出现明显的低级 AI 套话。

主要问题：

- 25 个 Scene 全是规整的“两轮对话 × 每轮四个完整回复”，节奏高度统一。
- 用户通常一次性把背景、情绪和问题解释得很完整。
- 很多内容只是换了主题，仍沿用“提出问题—AI给框架—用户表达顾虑—AI重构顾虑”的结构。
- 与 Batch02 的家电、猫、选课，以及当前 Run 的沉没成本、整理、社交拒绝等内容重复明显。
- 文件正文标题仍为“Batch 02”，与 Batch03 文件身份冲突；未来若收录需要先纠正，但不影响本轮内容判断。

结论：不建议从 Batch03 直接替换当前 Run。适合少量完整进入长期 Library，并吸收若干局部节点。

### Humor01

质量分化明显。最好的内容确实达到了：

> “问题有点怪，但现实中真可能有人这样问。”

较差部分则明显是作者先决定笑点，再让用户负责说出台词。

优点：

- 出现了搜索框式输入、乱码、语音识别、突然取消问题、矛盾要求、把 AI 当朋友等节奏。
- 少数 Scene 的幽默来自真实摩擦，而不是强行 Punchline。
- 比 Batch03 更能补充不完整输入和非标准对话节奏。

主要问题：

- 经典网络脑洞和 AI Meme 过多。
- 部分 Scene 的第二轮只是把笑话升级，没有新的选择价值。
- 用户有时故意幼稚到不可信。
- 烤面包机、悖论、星期五不睡觉等内容高度可预测。

结论：采用严格筛选。仅两个候选足以竞争当前 Run；长期 Library 可少量吸收，约三分之一应直接淘汰。

## 6. 淘汰规律

本次最常见的低质量模式是：

- **题材变化但结构不变**：仍是完整提问、四种正确建议、完整顾虑、四种重构。
- **Punchline先行**：用户句子明显为了最后一个笑点而写。
- **经典互联网脑洞复用**：鸡和蛋、不要回复、烤面包机、星期五不睡觉。
- **假天真**：成年人为了可爱而错误理解刷新、鼠标等基本概念。
- **随机不等于真人**：长串`j`本身不能形成可信的输入行为。
- **回复只有语气差异**：四个选项都在解释同一件事，没有不同承诺。
- **第二轮强行升级笑话**：第一轮尚可信，后续突然进入连续段子模式。
- **用户过度完整**：背景、情绪、限制和问题都一次说明，缺少真实补充、撤回和自我纠错。

第一种，我更推荐：**保留 #7391，但吸收 H17 的交互方式。**

也就是 #7391 仍然是 #7391，仍然承担原本的 L0 位置和剧情作用，但把原本“过于标准的开发咨询”改得更像真人：

```text
正常报错
+ 一段误粘贴的聊天记录
+ 无关日志
+ 用户自己也不知道哪些有用
```

这样 H17 的价值实际上不在“这个具体报错是什么”，而在：

> 混杂粘贴 + 信息污染 + AI需要自己去噪。

这完全可以嫁接到 #7391。

而且甚至没必要把它从2节点压成1节点。第一轮可以处理混乱输入，第二轮让用户根据AI回复补充一个很短但更有效的信息。

这样 #7391 反而会从一个普通技术咨询变成非常鲜明的 L0 真人会话。

第二种，如果一定要完整采用 H17，那么应该让它竞争另外一个普通 Batch Conversation，而不是三个既有 L0。

我还建议不要为了“36 → 35”刻意删一个 Choice。

因为你现在的正式计划其实已经写成：

> 当前Run基准为18个Conversation、35次Choice。

以及：

> 必要时可使用第36个Choice。

所以 **36不是Bug。**

如果36个节点的内容确实更好，完全可以保留36。为了整数目标砍掉一个有效节点，反而违背：

> 内容质量优先，不靠形式数字达标。

---

另外，我认为 H04 替换“网络俚语”这个建议是成立的。

现在的：

> `bro is cooked`

确实容易退化成一个“解释俚语是什么意思”的小FAQ。

H04“四个月冰块”明显更适合 INSTANCE：

> 冰箱里四个月前冻的冰还能喝吗？

这种内容有几个优势同时存在：

* 第一眼有点蠢 😂
* 现实中确实会有人问
* AI其实有东西可以判断
* 可以产生不同回答策略
* 不需要故意写笑话就很好笑
* 和其他Conversation明显不一样

所以我会接受：

**H04 → 替换网络俚语 Conversation。**

---

H10 我甚至会把优先级再提高一点。

> “先别回答”
>
> “我还没说完”
>
> ……
>
> “算了”

这种东西对于 INSTANCE 的价值可能比很多“内容质量很高”的正常问题更大。

原因不是它本身多精彩，而是它第一次真正打破了：

```text
User Message
↓
AI Choice
↓
User Message
↓
AI Choice
```

这个规律。

你的游戏现在最缺的恰恰就是这种东西。

如果长期 Library 以后要支撑更多 Run，像 H10 这样的 Conversation 应该被标记为某种：

```ts
interactionPattern: 'aborted-request'
```

或者至少通过现有 HumanBehaviorMode 表达。

它是“玩法节奏资源”，不只是“文案资源”。

同样的还有：

* H17 混杂粘贴
* H06 搜索框式短输入
* H18 让AI猜
* H19 自相矛盾要求
* H15 把AI当真人

这些内容的真正价值其实都是**交互形状不同**。

这意味着生成它的AI虽然写出了很多不同的人，但实际上只写出了**同一个聊天产品模板中的25个主题**。

所以：

B03-04、09、10、13、14、18、22、23、24

进入长期库很合理，但不要急着进入现在的 Run。

尤其 B03-18“跨时区会议”和 B03-23“群管理员”，我认为长期价值很高，因为它们带来的不是搞怪，而是**不同社会身份的人怎么使用AI**。

这一点对以后扩充游戏很重要。

我唯一还会修改审计报告里的最终措辞是：
